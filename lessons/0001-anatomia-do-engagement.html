A anatomia de um engagement

Os 8 estágios do seu pipeline, do preflight ao purge — e a decisão de arquitetura que sustenta tudo: o funil de confiança.

Ligação com a missão: antes do primeiro spot-check de €500, o T8 exige 2 dry-runs em ≤4h. Você não fecha 4h de wall-clock consultando o design doc a cada passo — o fluxo precisa estar na memória. Esta lição constrói essa espinha dorsal; as próximas penduram profundidade nela.

A ideia central: um funil de confiança

O seu pipeline não é uma lista de ferramentas — é um funil que converte output bruto de ferramenta em afirmação defensável, estreitando o que cada camada pode ver: 

ferramenta (JSON bruto, em disco)  →  skill (resumo estruturado ≤1k tokens)  →  report agent (só os resumos)  →  relatório (com trilha de auditoria)

A regra que faz o funil funcionar: o Report Agent nunca lê o output bruto — só os resumos. Isso limita alucinação (o agente não pode "citar" o que nunca viu), mantém o contexto dentro do orçamento, e garante que todo achado no relatório tenha um arquivo em tool-outputs/ como evidência rastreável. Quando uma skill falha, o funil não disfarça: o relatório mostra um bloco SECTION UNAVAILABLE visível, nomeando ferramenta e motivo.

Cada uma escreve o bruto em disco e devolve resumo ≤1k tokens + status OK/DEGRADED/FAILED.
